# Столик — приложение для бронирования столиков

Учебный фронтенд на React и TypeScript для подбора ресторана, выбора столиков и управления бронированиями. Данные ресторанов демонстрационные, брони локальные: приложение не отправляет заявки в реальные рестораны.

## Запуск

Нужны Node.js 22 или новее и npm. В PowerShell откройте эту папку:

```powershell
npm.cmd ci
npm.cmd start
```

Откройте http://127.0.0.1:3001. Остановка — Ctrl+C в терминале. Используйте один и тот же адрес: хранилища `localhost` и `127.0.0.1` различаются.

## Проверки

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
```

Для браузерных тестов нужен установленный Google Chrome и запущенный `npm.cmd start` в другом терминале:

```powershell
npm.cmd run test:browser
```

Тесты запускают отдельный изолированный контекст Chrome, не трогают пользовательский профиль и сохраняют снимки и JSON-отчёт в `test-results`. Проверено 28 юнит-тестов и 18 групп браузерных проверок. Браузерные тесты проверяют видимые элементы и сценарии, юнит-тесты — правила бронирования и отказ хранилища.

## Демонстрация

1. Выберите дату в будущем, время 09:00–21:00 и число гостей.
2. Выберите сортировку по ожиданию или среднему чеку.
3. Нажмите «Выбрать столик», отметьте один или несколько свободных столиков.
4. Введите вымышленное имя и телефон, например «Тестовый Гость», `+7 900 000-00-00`.
5. Сохраните демобронь и перейдите в «Мои бронирования».
6. Перезагрузите страницу, проверьте сохранение. Отмените бронь с подтверждением.

## Реализовано

- Каталог, фильтрация по суммарному числу свободных мест, две сортировки.
- Страница ресторана, доступные столики на выбранный интервал, выбор нескольких столов.
- Двухчасовой интервал, исключение пересечений, повторная проверка перед записью.
- Проверка имени, телефона, даты, времени, целого числа гостей и вместимости.
- Хранение в localStorage, подтверждение сохранения, список и фильтры, отмена.
- Явные ошибки повреждённого/недоступного хранилища без молчаливой перезаписи.
- Адаптивная компоновка, клавиатурные кнопки, нативный dialog с Escape, возврат фокуса.
- Прямые ссылки и обновление вложенных страниц через historyApiFallback.

## Ограничения

Это автономная демонстрация фронтенда, без общего серверного состояния, авторизации, платежей, рассылок и подтверждения рестораном. Локальная запись не заменяет серверную транзакцию: одновременная запись из нескольких вкладок может конфликтовать. Обновление по событию storage и повторная проверка сокращают риск, но не дают атомарности.

Данные привязаны к браузеру и адресу сайта. Очистка данных сайта удаляет брони. Хранение контактных данных не зашифровано; используйте тестовые данные. Время берётся по локальным часам устройства. Схема столиков условная, сведения о кухне и описания ресторанов демонстрационные. Реальные цены и доступность не запрашиваются.

## Сборка для размещения

`npm.cmd run build` создаёт `dist`. Нужен HTTP-сервер с перенаправлением неизвестных путей на `index.html` для маршрутов React Router. Открытие index.html через `file://` не поддерживается.

## Структура

`src/domain/booking.ts` — типы, демоданные, правила интервалов, класс BookingRepository.
`src/blocks/<block>/<block>.tsx` — React-компоненты интерфейса, включая страницы.
`src/blocks/<block>/<block>.css` — стили соответствующего БЭМ-блока, его элементов, модификаторов и адаптивных состояний.
`src/styles/base.css` — базовая типографика, сброс и клавиатурный фокус.
`src/styles/index.css` — единая точка подключения стилей.
`scripts` — воспроизводимые проверки.

Параметры ресторанов являются демонстрационными. Правило двухчасовой брони реализовано и проверяется в доменной модели. Код отформатирован Prettier.

## БЭМ

Используется схема **flex**: каждому блоку соответствует каталог с одноимёнными файлами. Например, `src/blocks/restaurant-card/restaurant-card.tsx` и `restaurant-card.css`. Элементы и модификаторы компактного блока находятся в его CSS-файле. Имена: `restaurant-card`, `restaurant-card__title`, `restaurant-card__art_theme_2`; состояние столика — `table-map__table_selected`. Модификатор используется вместе с базовым классом. Смешение блоков: `button restaurant-card__action`.

Правила бронирования в `src/domain`, конфигурация сборки и тесты не являются визуальными БЭМ-блоками и остаются в отдельных функциональных каталогах. Описание схемы: https://bem.info/ru/methodology/filestructure/.

Проверка структуры и селекторов: `npm.cmd run check:bem`.

## Доработка интерфейса и анимации

Форма показывает этапы бронирования и выделяет текущий этап по выбранной вместимости. Число выбранных мест объявляется через `aria-live="polite"`. Диалог появляется за 180 ms, подтверждение сохранения — за 200 ms; цвет столика меняется за 160 ms. Все новые эффекты отключаются при `prefers-reduced-motion: reduce`. При отсутствии поддержки CSS `@starting-style` появление происходит без анимации.

Дополнительная проверка нормального и уменьшенного движения, индикатора этапов и мобильного переполнения: `node scripts/test-motion.cjs`. Нужны Chrome и запущенный сервер. Отчёт: `test-results/motion-report.json`; снимок актуальной формы: `test-results/form-refined.png`.

## Светлая и тёмная темы

Кнопка в шапке переключает тему. При первом открытии используется настройка системы; ручной выбор сохраняется в localStorage (`stolik-theme`). Изменения системной темы применяются до ручного выбора. При недоступном хранилище переключение работает только в текущем сеансе.

Цветовые переменные — `src/styles/base.css`, компонент БЭМ — `src/blocks/theme-toggle`, управление предпочтениями — `src/domain/theme.ts`. Нативные поля используют `color-scheme`. Кнопка доступна с клавиатуры и сообщает состояние через `aria-pressed`.

Проверка: `npm.cmd run test:theme` (Chrome и сервер на http://127.0.0.1:3001). Отчёт: `test-results/theme-report.json`.
